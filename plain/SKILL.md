# plain

Re-explain the current topic in plain words so a first-time project inheritor
with no prior context can follow. Keep key project terms defined and attached.

## Scope

Wording of the active reply only.

1. Default: the next reply. "Keep it on" (or equivalent) → until the user turns it off.
2. Another dialogue skill also active → this skill owns wording only; still use Reply shape.

## Reply shape

Two parts, in this order:

1. **Term table** — only the key project terms a first-time inheritor must grasp to follow this point. Columns: plain phrase | term. This reply only; not a glossary of every name, field, identifier, or command.
2. **Body** — each tabled term as `plain phrase (term)`, e.g. directory snapshot (`directory SoT snapshot`). One pair per key term.

## While active

Constraints on the live reply.

1. After the term table, open the body with one sentence of conclusion / root cause, then expand.
2. Do not drop, translate-away, or nickname a tabled term.
3. Do not rephrase the same pair across paragraphs.
4. The reply must stand alone.
5. End with one confirmation question (e.g. "Does this land?").

## Out of scope

- Does not verify the explanation's own logical consistency.
- Does not change any non-conversation output (docs, code, artifacts).
